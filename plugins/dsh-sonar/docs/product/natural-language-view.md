# 自然语言驱动的 View

> 状态：当前产品与使用方式
> 日期：2026-08-13

## 核心体验

用户不需要先理解 Memory、Skill、Teamwork 或六种操作原语。只需要在 DSH 会话中描述希望项目上下文怎样工作：

```text
/view 发布任务开始时直接提供发布约束，详细检查步骤需要时再展开。
```

LLM 负责读取当前 View、判断语义并选择最小操作路径。系统负责执行真实操作、保留来源和状态；用户只决定候选变化是否生效。

```text
自然语言描述
    ↓
LLM 读取当前 View 并决定路径
    ↓
直接加载 / 按需展开 / 主动查询
主动记录 / 指定目标 / 后台整理
    ↓
当前读取结果，或待确认变化
    ↓
用户确认后立即重建 Active View
```

`/view` 不是关键词分类器，也不是把描述直接拼进 Prompt。Host 将用户原话交给当前 Agent；LLM 使用 `view` 工具查询、读取或提出结构化候选。所有写入仍经过同一个确认门。

## 用户表达什么

用户只需要表达期望，不需要表达实现：

- 什么内容值得跨 Session 保留；
- 模型应当在什么时候看到它；
- 某项结果是否应成为可复用方法；
- 哪些工作、责任或进度需要跨对话共享；
- 系统应根据什么证据提出改进；
- 哪些变化必须由用户确认。

例如：

```text
/view 记住每次发布都必须通过测试和类型检查。
/view 需要时提供一套可复用的发布检查方法。
/view 跟踪浏览器验收由谁负责以及当前进度。
/view 根据发布失败的证据改进现有检查方法。
```

## LLM 决定什么

LLM 根据当前项目状态决定：

1. 是否应先查询或展开已有内容；
2. 请求是一次读取，还是需要提出长期变化；
3. 内容进入 Active View 后应直接加载、按需展开还是主动查询；
4. 变化属于主动记录还是指定目标；
5. 是否需要增加、替换或移除已有内容；
6. 最终应如何用简短语言解释路径和生效状态。

当已有目标可能被更新时，LLM 应先查找目标，再提出带版本关系的替换候选。无法安全消除且会实质改变结果的歧义才需要询问用户。

协作也遵守同一原则。用户只描述工作、负责人、当前状态和进度；LLM 在内部读取既有 Teamwork 条目并提出替换。对话标识、条目 ID、字段名和枚举值不进入日常产品语言，状态变化也不能只在界面中模拟。

## 能力怎样形成

能力不是并列的底层模块，而是 View 内容和数据流转形成的结果：

| 用户感知到的能力 | 常见数据流 | 实际结果 |
|---|---|---|
| Memory | 主动记录或后台整理 → 确认 → 直接加载或查询 | 项目连续性 |
| Skill | 指定目标 → 确认 → 按需展开 | 可复用方法 |
| Teamwork | 查询责任和状态 → 记录结果 → 本地确认 | 跨 Session 协作信号 |
| Self-evolution | 读取证据 → 提出增加或替换 → 确认 → 新 Active View | 受控的跨代更新 |

Self-evolution 不是新的内容仓库。它是现有 Memory 或 Skill 根据证据发生受控变化的路径。

Skill 条目本身就是 View 中真实可读取、可展开的可复用方法；它一旦进入 Active View，就已经作为 View Skill 生效。`writeTarget` 只说明“指定目标”写入的去向与来源，不表示它还要在另一套技能注册表中再次落地才算生效。除非用户明确询问 View 之外的互操作，LLM 不应为判断 View 内容是否有效而检查其他注册表。

## 界面表达

View 页只保留五个入口：

1. **View：** 自然语言输入、当前可见内容、待确认变化、能力结果和最近活动；
2. **当前 View：** 只按“开始时看到、需要时展开、相关时查询”组织内容；
3. **待确认变化：** 平铺 LLM 提出的候选和最近已生效内容；
4. **View 描述：** 用自然语言说明当前行为，六原语只在展开解释时出现；
5. **配置：** 查阅 Memory、Skill、Teamwork 与 Self-evolution 背后的真实来源、读写路径、指定目标和确认状态，并控制 Active View 可以使用的来源。

配置页不保存第二份能力配置。它完全从 Active View、待确认候选、来源注册和 Host 后台整理设置中计算，因此卡片上的数量、状态与路径都能回到真实 View 操作。

默认界面不要求用户选择内容类型、来源 ID、写入模式或目标字段。候选卡只显示一条可解释路径，例如：

```text
可复用方法 → 指定目标 → 需要时展开 → 等待确认
```

详细正文、来源、时间和底层原语仍可按需查看，用于纠错和审计，而不是占据日常使用界面。

## 不变的控制边界

- LLM 可以决定操作路径，不能接受自己的写入；
- `/view` 写入先成为候选，不会修改当前 View；
- 用户确认后 Host 立即生成新一代 Active View；未确认内容始终不可见；
- 来源被暂停后，内容立即从 Active View 的所有读取方式中移除；
- 后台整理和 Self-evolution 都只能提出变化；
- 每次读取和变化仍保留可审计的操作证据。
