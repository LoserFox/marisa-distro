## 真实 DSH 闭环

插件通过原生 `◇ View` 页签和 `/view` 命令进入 DSH，不引入独立应用壳。验收使用独立工作目录、独立状态文件和端口 `43931` 启动真实 DSH Web Runtime。

### Memory 与 Skill

实际发送自然语言：

```text
/view 记住：能力验收时，所有写入都必须经过用户确认；以后开始相关任务时直接告诉模型。
```

LLM 读取当前 View 后提出“记忆 → 主动记录 → 直接加载”候选。确认前当前内容不变；点击“接受并生效”后，页面直接切换到新 generation，Memory 立即出现在“开始时直接看到”。

另一次请求把“能力验收方法”保存为按需展开的 Skill。确认后在“当前 View”点击展开，真实 RPC 返回完整方法，而不是静态演示正文。

### Teamwork 实时更新

先创建由小林负责的浏览器验收工作，再在新的 DSH Session 中实际发送：

```text
/view 小林已经开始浏览器验收，目前完成一半。请更新这项工作的状态和进度。
```

LLM 读取既有协作条目并提出替换。确认后没有重启 Runtime，页面立即从 generation 4 切换到 generation 5；配置页同时显示负责人“小林”、状态“进行中”、进度“50%”。用户自然语言和最终回复中都不需要内部标识、字段名或枚举值。

随后发送：

```text
/view 小林已经完成浏览器验收，结果是新配置页与四项能力都通过真实操作验证。请更新协作结果。
```

确认后 generation 6 立即显示“已完成、100%”。开启的后台整理从这个真实完成证据派生一条 Memory 候选；它仍等待用户确认。确认该候选后 generation 7 的 Memory 数量从 1 增至 2。

### Self-evolution 真实替换

实际发送：

```text
/view 根据这次验收证据改进“能力验收方法”：确认后应当立即核对 Active View，不再要求重启 Runtime，也不要再核对所谓未来 View。
```

LLM 先展开既有 Skill，再提出带替换关系的新版本。确认后页面立即进入 generation 8；无需重启即可重新展开正文，看到新的四步方法“查当前 View → 执行真实操作 → 用户确认 → 立即核对 Active View”。这证明 Self-evolution 是有证据、需确认、可读取的真实替换，而不是单独的展示分类。

## 界面与配置

1. View 页只保留 View、当前 View、待确认变化、View 描述、配置五个入口；
2. 配置页四张卡完全由 Active View、待确认候选、来源和后台整理配置计算；
3. Teamwork 卡展示自然语言状态、负责人和进度，不要求技术标识；
4. 来源开关真实影响三种读取路径；
5. 确认、拒绝与来源开关通过 RPC 回包直接刷新当前页，默认 500ms 轮询只用于同步其他会话或 Runtime 的变化；
6. DSH 插件配置页可把语言、刷新间隔、动画和后台整理覆盖写入 `.dsh/settings.yaml`，并由 Host 实时应用；
7. 动画只表达请求交付和候选进入，减弱动画配置会关闭非必要运动。

浏览器控制台未出现插件错误。服务重载时只观察到连接重试，重连后 View 能从持久状态准确恢复。

## 当前边界

- `local-preview` 用于验证操作和产品形态，不替代权威 provider；
- 一个 Runtime 对应一个配置的项目 workspace；
- 读取前会刷新共享状态；并发写入的强一致性仍由后续权威 provider 负责；
- 每个 generation 保持不可变，确认只切换 Active View 指针，不反向修改已经开始的模型输出。
