# 自然语言 View 界面

> 状态：当前 UI 设计与实现说明
> 日期：2026-08-13

## 目标

界面不再把六种原语、内容类型、来源统计和活动过滤器同时铺成一个基础设施看板。日常入口只有一句自然语言：

```text
/view 描述项目应当怎样被看见、记住、协作或改进
```

LLM 决定怎样读取当前 View、是否提出变化、内容确认后怎样可见。UI 负责三件事：

1. 让用户自然地表达期望；
2. 解释 LLM 选择了什么路径；
3. 保留对候选、生效 View 和来源的最终控制。

## 五个界面入口

### View

首页包含自然语言输入框、四条示例、当前可见内容与变化控制的简要数字、能力结果、最多三条待确认变化和最近活动。

首页提交复用 DSH 会话输入机：插件写入 `/view <描述>` 并提交，DSH 的原生命令将描述交给当前 Agent。前端不会自行分析关键词或直接写入状态。

### 当前 View

当前内容只按可见时机分为三组：

- 开始时直接看到；
- 需要时可以展开；
- 相关时可以查询。

按需展开仍调用真实读取 RPC；主动查询仍只搜索 `readMode=query` 的 Active View 内容。内容类型只作为小标签出现。

### 待确认变化

页面平铺所有待确认候选。每条候选用一行路径解释 LLM 的选择：

```text
能力结果 → 写入方式 → 生效后的读取方式 → 等待确认
```

用户可以接受或拒绝。接受后 Host 立即生成新的 Active View 代际，同一页面马上显示已生效内容；不再等待超时或 Runtime 重启。

### View 描述

页面把结构化条目转换为自然语言行为，例如：

```text
从开始就向模型提供“发布约束”
需要时让模型展开“发布检查方法”
在相关任务中允许查询“浏览器验收责任”
```

六种底层操作位于折叠说明中，用于解释自然语言最终选择了什么路径。

### 配置

配置页用四张卡说明 Memory、Skill、Teamwork 与 Self-evolution 当前是怎样形成的。所有内容都来自真实状态：

- Memory、Skill、Teamwork 展示内容来源、读取路径、已经发生的写入、指定目标、当前与待确认数量；
- Teamwork 额外展示负责人、自然语言状态和进度，不要求用户提供对话标识；
- Self-evolution 展示证据读取、作用内容、增加/替换路径、确认门和后台整理状态；
- 内容来源控制从 View 描述移动到这里，开关会立即重建 Active View。

配置页没有第二份浏览器状态，也不会为了演示生成虚假的能力或进度。

## 能力结果

首页展示 Memory、Skill、Teamwork 与 Self-evolution 四个紧凑结果卡。数字来自 Active View 与候选的真实状态：

- Memory、Skill、Teamwork 按内容类型计算；
- Self-evolution 按替换关系或有来源的派生变化计算；
- 卡片不可切换操作路径，也不会建立第二套状态。

Self-evolution 只是一条受控数据流：读取证据，提出 Memory 或 Skill 的增加或替换，用户确认后立即进入新一代 Active View。

## 动画语义

动画只在两个时刻出现：

- 发送自然语言请求时，输入区域短暂扩散，表示请求已交给 LLM；
- 新候选出现时，卡片轻微进入，表示变化正在等待确认。

页面没有持续粒子、循环连线或常驻路径动画。`motion=reduced` 和系统减弱动画设置会关闭这些效果。

## 插件运行配置

Cordis 插件配置仍提供部署基线。DSH「设置 → 插件配置 → View 基础设施」允许用户实时覆盖语言、刷新、动画和后台整理，值写入 `$DSH_HOME/settings.yaml` 的 `dsh-sonar` 节。

确认、拒绝和来源切换通过 RPC 返回直接更新当前页，不等待轮询。其他会话或 Runtime 的看板以 500ms 为默认同步间隔；模型的下一次 `status`、`query`、`read` 或 Prompt 构建则直接刷新权威状态，不等待该间隔。

`workspace` 与 `storagePath` 仍只属于部署配置。自然语言入口不能切换项目权威状态位置。
