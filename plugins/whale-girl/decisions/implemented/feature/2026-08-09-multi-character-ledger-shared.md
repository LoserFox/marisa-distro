# Decision: 多角色账本——资历归陪伴关系（共享账本，不做按角色分账本）

Status: implemented

## Problem

角色清单化（2026-08-09）支持多角色后，账本归属出现语义问题：若按角色分账本（每个角色独立等级/称号/回忆），换角色 = 新的养成开始；若共享（现状），换角色后新角色继承旧资历。产品定夺（2026-08-09）：**选 A——资历归陪伴关系，共享账本**。

## Decision

- **资历属于「用户与工作台的共同经历」，不属于某个角色皮套**——换角色是**外观**变化（角色清单/动画/素材全量契约，见 [asset-full-contract](2026-08-09-asset-full-contract.md)），资历是**关系**积累（任务/会话/陪伴时长），两个维度正交。
- 账本保持单一 `state.json`（`<dshHome>/data/dsh-pet/state.json`），不做按角色 key 分账本；角色切换只影响显示层（characterId/资源/尺寸），不影响账本读写。
- 产品心智：宠物是「同一个伙伴换皮肤」，不是「多个独立伙伴」。

## Alternatives considered

**B：按角色分账本（每个角色独立 level/xp/titles/memory）。** 每角色独立养成、多周目收集感更强——但：① 违背「积累型伙伴」核心语义（资历是关系不是皮套）；② 实现成本高（state.json 按角色 key + 现有数据迁移 + 切换时读对应账本 + 称号/回忆按角色分裂）；③ 换角色后看到 Lv.1 猫易误判「数据丢失」——弃。

## Consequences

- 换角色后新角色继承全部资历（等级/称号/回忆）——「换皮不换资历」，符合「关系积累」定位。
- 零实现成本（现状即共享）；多角色账本相关实现（账本 key 化/迁移/切换逻辑）不做。
- 已知边界：若未来转向「多独立伙伴收集」产品方向，需重新拍板（本决策记录即依据）。
