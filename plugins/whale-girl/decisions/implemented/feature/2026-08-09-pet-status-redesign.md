# Decision: 状态条 UI 重设计——顶部悬浮信息卡（锚定 + 翻转 + 让位）

Status: implemented

## Problem

手测反馈状态条「信息被宠物遮挡、UI 粗糙」。深入诊断发现根因不止视觉：status 是**流内元素排在 stage 下方**（opacity:0 仍占高约 44px），宿主盒 `host.offsetHeight` ≈ 160px 而非纯宠物 110px——① 拖拽 clamp 用 `host.offsetHeight`，宠物**永远无法贴到视口底边**；② 隐形区域拦截 hover/点击。11px 灰卡无层次、无锚定关系，与宠物无视觉连接。

## Decision

- **状态卡改绝对定位、锚定宠物顶部**（`bottom: calc(100% + 8px)`，脱离流式——不撑大宿主盒、不遮宠物本体）：宿主盒 = 纯 110px 宠物盒，拖拽 clamp 恢复准确（宠物能贴底），隐形拦截区消失。
- **视觉连接**：卡片与宠物间 8px 间隙 + 指向头顶的菱形连接尾（`::after` rotate 45°），尾巴命中区覆盖间隙保证 hover 连续不闪断。
- **视口感知翻转/对齐**（`layoutStatus`，hover 显示时计算）：宠物贴顶 → 卡翻到下方（尾巴朝上）；贴左右缘 → 卡边缘对齐宠物边缘（防伸到视口外）；硬钳制 8px 边距兜底。
- **配色**：暗色毛玻璃卡（`rgba(27,30,40,.94)` + blur），单一品牌蓝锚点 = Lv 徽章（`#B7C8FE` 于 `rgba(86,134,254,.16)`），其余灰度阶梯（主文 `#E8EBF2`、次级 `#AEB6C4`）；等宽数字（`tabular-nums`）防计数跳动。
- **信息密度**：严格两行——行一 Lv 徽章 + 任务计数（失败为 0 时省略「· 0 失败」）；行二最近回忆（ellipsis）/离线提示。
- **让位规则（零新增状态机）**：气泡激活（`activeBubble`）或拖拽中 → 状态卡隐藏（气泡/移动是主角）；`.pet-menu.open` → 状态卡隐藏（CSS `~` 兄弟选择器）。
- **动效**：入场 opacity + 6px 位移（200ms `cubic-bezier(.16,1,.3,1)` + 60ms 延迟，只作用于进入方向）；离场 150ms ease-out；隐藏用 `visibility:hidden` 延迟（淡出后移出可达性树）；reduced-motion 禁用全部过渡。
- **a11y**：保留 `:focus-within` 显示；`visibility:hidden` 隐藏态不进读屏树；对比度全部 ≥6:1（主文 ≈13:1）；不引入 aria-live（3s 轮询会周期性打断读屏）。

## Alternatives considered

**A：侧边卡（宠物左侧垂直居中）。** 右下角位时卡向左伸向视口中心，观感像便签而非宠物的一部分；左右两向翻转实现成本翻倍；更易遮用户正在看的内容——弃。

**B：保持下方流内布局仅美化。** 不解决「被遮挡」第一性问题（贴底空间天然不足 + 流内撑大宿主盒的拖拽隐患原样保留）——只美化是治标——弃。

## Consequences

- 状态卡悬浮于宠物头顶，宠物本体不再被遮挡；宿主盒变 110px，拖拽 clamp 准确（宠物可贴底）；气泡/拖拽/菜单三种场景状态卡正确让位。
- 已知边界：卡片显示时 `getBoundingClientRect()` 计算一次（hover 时宠物静止，无需连续监听）；极罕见场景（宠物贴顶 + 气泡 + 悬停同时）状态卡不显示（气泡是即时信息）。
- 关联：effects 层（爱心/气泡）z-index 2 > 状态卡 z-index 1 > 舞台，层级硬约束保证气泡永远在卡之上。
