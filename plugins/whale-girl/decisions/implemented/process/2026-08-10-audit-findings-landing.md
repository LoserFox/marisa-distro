# Decision: 审查漏洞落地——取代校验/门禁元校验/并行保护/重评检查点

Status: implemented

## Problem

六个独立 subagent 对 deep-standard 约束漏洞的审查（各自核验 skill 原文与仓库实证）确认 A~F 中的机械缺口真实存在，其中四项可在项目内落地：**A** 取代检查的输出契约（带链接/双向互链/归档闭环）无门禁；**B** 阶段取舍失效条件与档位重评无检查点；**C** 多 agent 并行修改无在途改动保护；**D** 门禁自证无元校验（gate-self-tests 的 glob 不校验对照，新增门禁忘写自证不会自然红）。

## Decision

- **A 取代检查门禁化**（verify-decisions 扩展）：记录中取代类声明（一方取代另一方）必须带相对路径链接；被取代方保持活跃的须含指向声明方的回链（双向互链）；取代到归档的声明其目标必须在 `archived/` 且带 `Archived:` 标记（归档闭环）。语义性「取代」（如「字段取代 X 语义」）不触发。自证 +5 条。
- **A 取代检查证据声明**（decisions/README.md 流程要求）：每条新记录须声明取代检查结果（无重叠 / 互链 / 归档）——识别重叠不可全机械化，声明本身由上述门禁校验链接契约。
- **D 门禁↔自证对照元校验**：新增 `verify-gate-self-coverage` 门禁（正则解析 run.mjs GATES，断言每个有实现的门禁存在 `<name>.test.mjs`；unit-tests/tool-tests/gate-self-tests 为测试组本身除外）。自证 +4 条。
- **C 并行/在途改动保护**：pre-commit hook 检测未暂存改动并列出（不阻止——未暂存合法，只暴露暂存范围）；AGENTS.md 约定「未暂存改动存在时禁用 `git add -A`，显式路径 add」。
- **B 重评检查点**：AGENTS.md「当前阶段取舍」节声明「分发/发布动作前必须重评本节失效条件与 deep-standard 档位，结论写入决策记录」——失效条件是否触发是语义判断（外部消费者/并行改动/契约面），检查点绑定分发前置流程，不尝试纯门禁化。

## Alternatives considered

**A：强制每条记录声明取代检查结果（门禁要求）。** 全树现有记录都会红（多数无重叠、无需声明），且「识别重叠」本身是语义判断——退化为形式主义。改为「声明由流程要求 + 声明出现时的链接契约由门禁校验」——弃全量强制。

**B：把失效条件触发做成门禁。** 「出现外部消费者/并行改动」不可机械判定（无可靠信号源）；门禁只能查「AGENTS.md 是否写了失效条件」的存在性，查不了触发。绑定分发动作 + 决策记录产出——弃门禁化。

**C：pre-commit 拒绝未暂存改动。** 正常开发中未暂存改动合法（分批提交场景），拒绝会逼 `--no-verify` 绕过。警告 + 显式路径纪律——弃拒绝。

**D：在 run.mjs 内联对照校验。** 编排器职责是聚合执行，加校验逻辑会与「门禁清单唯一归属」混层；独立门禁更符合「只拒绝一条不变量」——弃内联。

## Consequences

- verify-decisions 现在会拦截无链接/单向/未归档的取代声明（对现有树仅修正一处流程措辞，无实质误伤）；gate-self-tests 的盲区由 verify-gate-self-coverage 补上（未来新增门禁忘写自证会红）。
- 并行场景下提交会收到未暂存清单提醒，`git add -A` 被纪律禁止；分发动作有了显式的失效条件重评步骤。
- 项目门禁 15 → 16（verify-gate-self-coverage）；自证测试新增 9 条。
