# Decision: deep-standard 档位重评——首次分发时（adopt-l2 升档条件触发）

Status: implemented

## Problem

`decisions/implemented/process/2026-08-08-adopt-deep-standard-l2.md` 的升档触发条件：「出现外部消费者、多协作者并行改动、或契约面超过 4 个时，评估 L3」。首个版本对外分发（官方 repository-plugin 形态，GitHub 源可被任何用户消费）——**外部消费者条件触发**，按 AGENTS.md 分发前置检查点执行档位重评。

## Decision

重评结论：**维持 L2，不升 L3**（部分 L3 能力已提前具备）。

- **已有 L3 能力**：字数预算门禁（verify-doc-budget）、文档↔代码漂移门禁（verify-spec-states 状态/播放/优先级、verify-routes-sync 路由单一来源）——L3 的两项核心已在 L2 阶段落地，升档的边际收益缩小。
- **未装 L3 项**：覆盖率独立门禁、快照录制/重放体系。评估：宠物客户端行为面大（DOM 交互/状态序列），覆盖率门禁对纯函数面（logic.mjs 已 100% 覆盖核心路径）增益有限，DOM 面覆盖率工具成本高；快照体系当前无昂贵/不确定边界需要固化（验证靠 verify-client-behavior 探针）。
- **契约面**：官方 .dsh-plugin 契约（dsh 字段 3 键）+ 宿主服务 4 个（entry 工具已删，见 remove-agent-tools）——未超 4 个契约面的升档线（且官方 schema strict 限制了契约面增长）。
- **多协作者并行**：并行 agent 工作流已有（并行/在途改动保护已落地），但非持续外部协作者——不构成升档决定项。

**升档再触发条件**：出现持续外部协作者、契约面超过 4 个、或覆盖率高成本工具被证明确有收益时，重新评估 L3（覆盖率门禁/快照体系）。

## Alternatives considered

**A：升 L3（装覆盖率门禁 + 快照体系）。** 宠物行为面大半在 DOM（覆盖率工具成本高、收益低）；快照体系无适用边界；L3 门禁会成「永远不失败的空壳」（adopt-l2 原判据）——暂不升。

**B：只补覆盖率门禁（不装快照）。** 覆盖率门禁对纯函数面增益有限、对 DOM 面成本高；缺「死代码 vs 待补测试」的判定收益在当前规模不成立——维持。

## Consequences

- 首次分发后项目仍按 L2 运行；AGENTS.md 阶段取舍节更新为「已分发」状态（删除「可自由重命名与重组」过渡条款——公开 ref 被消费后改名破坏安装）。
- 字数预算/漂移门禁等已装 L3 能力继续守护；覆盖率/快照在再触发条件出现时评估。
