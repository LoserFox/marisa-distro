# 决策记录

一条**决策记录**记录一个决策或提案：动机、决定了什么、放弃了什么、后果、验证契约——代码和普通文档承载不了的那部分。本文件是这棵树的正门与契约。

## 布局与命名

路径形如 `{生命周期}/{分类}/yyyy-mm-dd-主题标题.md`，两个维度都编码在路径里。

**生命周期**（顶层目录，记录随状态在目录间移动）：

- `proposed/` — 实施前被评审的提案；尚未建成或只建了一部分。
- `implemented/` — 决策已落地，文件与实际形态保持同步。
- `rejected/` — 被考虑后否决。仅在其理由仍能阻止一个有诱惑力的错误时保留，否则整体删除。
- `archived/` — 已实施且理由不再可能指导未来工作的记录，**永久冻结**。

**分类**（嵌套目录，封闭集合，加分类要同时改本表与门禁）：

| 分类 | 覆盖 |
|------|------|
| `feature` | 新增的用户可见能力 |
| `bug-fix` | 修正缺陷，或补上事故复盘暴露的缺口 |
| `simplification` | 删除代码、行为或表面积，不新增能力 |
| `architecture` | 关于发布出去的源码的结构性决策 |
| `process` | 代码周边的工具、策略、流程——不是运行时行为 |
| `testing` | 测试基建与策略 |

文件名的日期是该主题**首次被提出**的日期。记录之间互相引用**用相对路径链接**，不用编号或纯散文——链接可被门禁校验，且在目录间移动后可修复。

**不建集中索引文件**：活跃的生命周期树本身就是清单。

## 什么时候必须写

**每个非平凡改动必须在同一 PR 内新增或更新至少一条记录。** 非平凡 = 改变了行为、架构、跨文件/跨模块契约、流程或工具、测试策略、on-disk/wire/配置格式，或任何维护者日后可能重新审视的决策。

- 更新已经拥有该决策的记录即满足；不要造重复件。
- 只有纯机械的、局部的、无行为/契约/结构/流程/理由变化的编辑豁免。
- **数量纪律**：能由现有记录覆盖的小修复优先**更新旧记录**（部分取代互链），不为每个小修复造新记录——记录的价值密度在「日后再审视时的理由」，不在四段齐全的仪式。
- **每条新记录都触发取代检查**：搜索活跃树里覆盖同一决策或机制的旧记录。完全取代 → 同一 PR 内归档旧件；部分取代 → 两条保持活跃并互链。**取代检查结果须在记录内声明**（无重叠 / 部分取代+链接 / 完全取代+归档）——「识别重叠」靠判断，「声明的链接契约」由 verify-decisions 门禁机械校验（声明必须带链接、部分取代双向互链、完全取代归档闭环）。
- 一条记录永远不会被改成另一个决策——用新记录取代它。

## 文件格式

头部三行固定，之后空一行：

```markdown
# Decision: <标题>

Status: <status>
```

`Status:` 的值与所在生命周期目录必须一致（门禁交叉校验）：`proposed` / `implemented` / `rejected — <一行原因>`。状态行不带日期、不带括注。

正文一律以 `## Problem` 开头（写成脱离解决方案也能读懂）。骨架按生命周期：

- `proposed/`：`## Problem` → `## Proposal` → …专门章节… → `## Alternatives considered` → `## Acceptance criteria` → `## Risks`
- `implemented/`：`## Problem` → `## Decision` → …专门章节… → `## Alternatives considered` → `## Consequences`
- `rejected/`：被冻结的提案，保留提案期章节，结论在状态行。

`## Proposal` 可用将来时；`## Decision` 用现在时描述已落地的现实。**提案期标题在已实施记录里被门禁拒绝**：`## Proposal`、`## Plan`、`## Migration plan`、`## Acceptance criteria`。

**`## Alternatives considered` 强制存在**：每个真实存在过的备选方案一段，写它为何落败。备选方案只能记录，不能编造；历史遗留文件无法重建时用固定标记声明，门禁仅对该标记之前的旧文件接受：

```markdown
<!-- decision-format: alternatives-not-recorded (pre-format record) -->
```

生命周期间移动 = 更新 `Status:` 行 + 重新满足该目录的骨架，同一个改动内完成。

## 归档与删除

归档判据：已实施、决策完整、且理由**不太可能指导未来工作**。只要备选方案、所有权边界、否定性保证、持久化/wire 语义、安全规则、或重新引入的条件仍然有用，就保持活跃。**绝不归档提案**——过时的提案要么否决要么更新。

归档动作：全部关联文件一起移入 `archived/{分类}/`，保留 `Status: implemented`，在状态行下方插入 `Archived: YYYY-MM-DD`，修复或删除入站链接。**这是归档过程中唯一允许的内容改动。**

封存即**永久冻结**：不得编辑、翻译、重排、移动、删除，也不得当作当前行为的依据。文档门禁跳过归档内容（含其出站链接）。

## 门禁

| 命令 | 拒绝什么 |
|------|---------|
| `node scripts/gates/verify-decisions.mjs` | 头部缺失、状态行与目录不一致、必需章节缺失、已实施记录里出现规划语气标题、分类在封闭集合之外、文件名不带日期 |
| `node scripts/gates/verify-md-links.mjs` | 相对链接指向不存在的文件 |
