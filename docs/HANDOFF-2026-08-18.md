## 坑与教训（避免重蹈）

1. **pnpm 11 嵌套 workspace**：成员目录内的 `pnpm-workspace.yaml` 触发独立安装（双重 store 1.3GB）。staged 树已排除 harness/pnpm-workspace.yaml；**lockfile 生成时不能有嵌套文件在位**（移走 → install → 移回）。`dsh-mygo/pnpm-workspace.yaml` 已删。
2. **file: 包依赖不 hoist 到根**：实体化包的依赖装在包自己的 node_modules。根治 = **根显式依赖全部 workspace 成员 + file: 包**（`pnpm -r list --depth -1 --json` 枚举成员）。
3. **实体包 peer 不自动装**（workspace peer）：根补齐 peer 闭包。
4. **`git stash create` 的 commit hash 含时间戳**（永远变）—— key 用 **`^{tree}`**（内容稳定），加 `-u` 含未跟踪文件。
5. **MyGO 是私有仓库**（r05en1cu）—— npm 包是旧发布渠道；正确来源 = `omdsh-dev/dsh-mygo@next`（vendored）。
6. **profile workspace 必须含 plugins/bundles**：插件旧范围依赖（`^0.0.1-rc.x`）否则解析到 registry 旧版（`dsh-compact` 404）。
7. **验证用 stage-boot（秒级）**，不要每次重打包（10 分钟）。
8. **网络**：pnpm 走代理 `127.0.0.1:10808`（记忆已有）。
9. **PowerShell 工具**递归删除会被静态拦截（用 `cmd rmdir /s /q` 或 .NET）。
